The Desk selection contract

The Desk is a concise opportunity set of Cassie calls, not a transcript of every routed post.

System map

The indexer produces routed Cassie calls and stores them on trade_ideas and routes. Once routed, every idea has the same product status. Pipeline metadata such as stated_by_author and trade_type must never filter, rank, label, or explain calls in the terminal.

Selection and ordering

StageRulePurpose
Selectroutes.status = routedInclude every Cassie call that has a tradable route.
OrderHigh, medium, then low conviction; newest first within each tier.Put stronger pipeline judgments first.
CollapseOne row per normalized ticker and direction.Prevent repeated coverage from crowding out distinct trades.
PriceOnly the selected rows receive live venue requests.Keep feed latency proportional to what the user sees.

Example

Five long USO calls compete for one USO:long slot. The highest-conviction, newest call represents that opportunity. A USO short remains separate because it is a different trade.

Verification

Build verification checks the query and response types. Runtime verification checks that pipeline classifications do not affect inclusion, ticker-direction keys are unique, and the returned set respects the requested limit.
